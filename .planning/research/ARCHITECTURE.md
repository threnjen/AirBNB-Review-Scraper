# Architecture

**Domain:** XGBoost ADR Prediction Model + Flask Web UI
**Researched:** 2026-03-08

---

## Pattern Overview

**Two-subsystem architecture:** `ml/train.py` (offline, run once) and `app/app.py` (Flask server) are coupled only through a model artifact file on disk.

---

## Components

### Training Subsystem (`ml/`)

- **Purpose:** Load CSV, select features, train XGBoost model with 5-fold CV, save model artifact + feature column list
- **Input:** `outputs/06_details_results/property_amenities_matrix_cleaned_97067.csv`
- **Output:** `ml/model/adr_model.joblib`, `ml/model/feature_columns.json`
- **Runs:** Once (or re-run manually after data update)
- **Dependencies:** pandas, numpy, xgboost, scikit-learn, joblib

### Model Artifacts

- `adr_model.joblib` — trained XGBRegressor
- `feature_columns.json` — ordered list of 146 feature column names (capacity, bedrooms, beds, bathrooms + 142 SYSTEM_ columns)

**Critical:** The feature column list is the contract between training and serving. Without it, feature vector column order at prediction time may differ from training — producing silently wrong predictions.

### Flask Web App (`app/`)

- **Purpose:** Serve HTML form, assemble feature vector from POST data, return ADR prediction
- **Routes:** `GET /` → render form, `POST /predict` → predict and display result
- **Model loading:** Once at module scope (startup), not per-request
- **Dependencies:** Flask, Jinja2, joblib, numpy

### HTML Templates (`app/templates/`)

- `index.html` — form with 4 numeric inputs + 142 binary checkboxes grouped by category
- Result rendered on same page or separate template

## Data Flow

```
CSV (479 rows × 150 cols)
  → ml/train.py: select features, drop property_id/Days_Avail/has_airdna_data/ADR
    → XGBRegressor.fit() with KFold(5) cross_val_score
      → joblib.dump(model) → ml/model/adr_model.joblib
      → json.dump(columns) → ml/model/feature_columns.json

User fills form (4 numeric + 142 checkboxes)
  → POST /predict
    → Flask handler reads feature_columns.json order
    → Builds numpy array: numeric values + (1 if checkbox present else 0)
    → model.predict(array) → float ADR
      → Render result as $XXX.XX
```

## Key Design Decisions

**Absent checkbox = 0:** HTML checkboxes only appear in `request.form` when checked. Feature vector builder must iterate `feature_columns.json` and use `1 if request.form.get(col) else 0` for every binary column.

**Model loading at startup:** `model = joblib.load(model_path)` at Flask module scope. Never inside the request handler.

**No changes to existing pipeline:** Reads the CSV as a static input. Existing `steps/`, `scraper/`, `review_aggregator/` packages are untouched.

**Build order:** `train.py` must run first (no Flask dependency) to produce artifacts. Flask app can be scaffolded in parallel but cannot start without the model file.

---

## Build Order

1. Training script (`ml/train.py`) — produces model artifacts
2. Flask app skeleton (`app/app.py`) — loads model, defines routes
3. HTML template — form with grouped checkboxes
4. Feature vector assembly + prediction handler
5. Result display + error handling
